    Preview feature status

    The published development release is 0.4.0-preview.2. The verified WSL user-local command also reports that version. See release evidence for the exact source and checks.

    This is an early Rust CLI for disposable analysis projects. A development preview does not mean the complete roadmap is finished. Use independent backups and sample data while evaluating it. The existing projr R package and thesis remain unchanged.

    Area Available Rust behavior Verification and limits
    Project selection Explicit root; nearest recognized ancestor; markerless cwd fallback; shallow default script discovery. Cross-platform fixtures cover markers, nested invocation and explicit override. Root recognition includes Python/Julia markers; that does not imply Julia execution or a wrapper.
    Configuration and init Active root YAML required; legacy alias/ambiguity rule; profile precedence; explicitly declared resource directories; local-only directory initialization. Cross-platform configuration/error-preservation fixtures. Old no-config roadmap assumptions were superseded.
    Execution context Ordered explicit scripts/hooks; native cwd with explicit project-root override; supported Quarto/R Markdown root controls; unsafe/unknown layouts fail early. Real Python/R/rendering acceptance and cross-platform fixtures passed. Direct R API/IDE parity remains unproved.
    Automation Opt-in protocol-v1 JSON, capability version, typed queries, noninteractive command worker, nonzero failures; child logs on stderr. Cross-platform machine tests. Static coarse error codes; no invented attempt/release record on success.
    Preview preservation The released CLI restores captured managed state after successful/failed previews. Cache results remain. Included through the reviewed recovery dependency; final integrated tests and actual released-binary checks passed. Generated-output path queries use the safe cache by default; arbitrary writes are not isolated.
    Production safety groundwork Path guards, bounded local failure recovery, optional checked Git publication and verified CAS bytes. Focused fixtures and reviews; incomplete release identity/provenance/retry model. This page is not an invitation to run on valuable production data.
    Binary delivery Development prerelease 0.4.0-preview.2 supplies versioned Linux/Windows x86-64 assets with mandatory checksums. Exact-tag workflow, uploaded/public asset hashes and both native binary smokes passed. WSL user-local installation and tiny success/failure Python previews passed. Other platforms are not supplied.

    Still unfinished: direct projr/quarto R API/RStudio parity, existing R helper integration, automatic isolation of every script write, durable attempt/release identifiers, complete input/code/config/dependency provenance, multi-writer/crash atomicity and analysis-free publication retry. Capture/recovery cannot undo arbitrary external script effects or guarantee concurrent readers never observe temporary changes. User/third-party logs are not automatically secret-redacted.

    M1 is delivered as the useful local CLI preview in 0.4.0-preview.2. It requires active root configuration; initialization is optional. Explicit file-based R/Python/report steps, captured context, inspectable cached results and honest structured failures work without Git credentials. Supported previews preserve recorded final/archive/version state on success and failure. Runtime path guards and preflight remain essential; arbitrary child code is not sandboxed.

    General command/argv forms, stronger process confinement and broader maintenance audits remain follow-ups. M2 records/provenance/retry and later frontend work are not completed by M1. See delivery boundaries, behavior and the compatibility log for supported details and remaining gaps.
