Run your first analysis

Calculate a mean and save a preview, using only Python’s standard library.

WarningTry it on a disposable project

Use sample data or a disposable copy of your project. Production builds (proj build) can modify or remove files, and safety fixes are still pending. Never run production builds on the only copy of important work. Previews are not a security sandbox; code you run can still change files.

NoteUse a current development build

This example targets the development preview on main, not the historical v0.3.0 package. See installation status first. The complete example was checked through the CLI in Ubuntu CI using source revision fafce46a and this documentation branch. Verification against a new release package is still pending.

1. Make a small project

In an Ubuntu terminal, choose a new folder and open it:

mkdir projcli-example
cd projcli-example

Create a file named _proj.yml with this content:

directories:
  raw-data:
    path: _raw_data
  cache:
    path: _tmp
  output:
    path: _output
build:
  scripts: [analysis.py]

The paths are explicit: runtime does not supply missing mappings or invent undeclared labels.

Label Folder Role in this example
raw-data _raw_data Input files; unused because our three measurements are built into the script.
cache _tmp Temporary results; the script writes inside _tmp/preview.
output _output Result files; unused by this preview.

Only cache is used by this Python example. The other two mappings match the local initializer’s preset. No docs path is implied: document rendering needs an explicit docs mapping too.

The explicit build.scripts list selects our one script. No Git setup, remote repository or initialization command is needed for this manual setup.

2. Add an analysis

Create analysis.py in the same folder:

import csv
import os
from pathlib import Path
from statistics import mean

root = Path(os.environ["PROJ_PROJECT_ROOT"])
preview = root / "_tmp" / "preview"
preview.mkdir(parents=True, exist_ok=True)

measurements = [10, 12, 14]
result = preview / "summary.csv"
with result.open("w", newline="") as handle:
    writer = csv.writer(handle)
    writer.writerow(["count", "mean"])
    writer.writerow([len(measurements), mean(measurements)])

print(f"Saved {result}")

The three measurements are deliberately built into the script so there is no data download or extra package installation. The script uses the project root provided by projcli and explicitly writes to _tmp/preview.

3. Check, then run

proj --project . yml read
proj --project . --non-interactive build-dev
cat _tmp/preview/summary.csv

The CSV should contain:

count,mean
3,12

The validation command reads configuration. The preview runs the script. Running it again replaces this example’s CSV; change a measurement and rerun to see the mean change.

4. Understand what changed

The script creates _tmp/preview/summary.csv. The CLI does not create a VERSION file, publish to docs, or export an archive during this preview.

A preview is not a sandbox: your script can still write elsewhere if you tell it to. Keep preview writes in an explicit temporary folder.

Starting another project

In another new project folder, local-only directory setup is available:

proj --project . --non-interactive init directories

When no base or active profile configuration exists, this writes _proj.yml with the explicit raw-data: _raw_data, cache: _tmp and output: _output paths, creates those folders, and updates ignore files. It does not run Git or GitHub setup. Existing configuration files are preserved; only their declared directories are created.

The generated file omits build.scripts, allowing the normal shallow script discovery. To choose an exact analysis, add a scripts list as above. An explicit scripts: [] selects no analysis scripts; hooks can still run. Initialization does not turn an absent scripts key into an empty list.

Where to go next

  • Query a declared path with proj --project . path get --label cache.
  • Add your own script to build.scripts.
  • Read the build reference before using proj build. Production builds have different version, cleanup and export behavior.
  • Check what works before adding document rendering or R tooling.
