projr compatibility and change log

The behavior contract owns current product decisions. This log records comparison evidence, implementation differences and gaps. Update it in every focused PR; do not infer runtime parity from similar source or green Rust CI.

Relationship labels are same, different, new, and unverified. Each entry states whether that label concerns documented intent, static source, or executed behavior. No comparative R runtime tests have been run for the entries below. Local R/Docker workloads have not been run.

Reference baselines

  • R baseline: SATVILab/projr at 3ac2959.
  • Thesis baseline: design at b110da5.
  • Rust pre-migration baseline: 024589b.

New comparisons must pin source commits and relevant files, record the decision and rationale, link executed tests, and distinguish approved, implemented and unverified behavior. Changing a reference baseline does not silently change the product contract.

PR123: development-preview mutation gates

  • Relationship: unverified runtime parity; same documented intent. The R README and thesis design describe development previews separately from publication. This is evidence of intent, not proof that every R development path is inert.
  • Decision/rationale: keep CLI-managed release/version/archive changes out of previews so researchers can inspect development results without publishing.
  • Implemented: PR123, merged 5d145293e596c5797e9620bd3f00978fa6f99411; Dev-gated VERSION writes, cleanup, document promotion, local export and ignore updates in build.rs, env.rs and yml.rs.
  • Executed evidence: three-platform Rust tests, including test_preview_safety.rs, and installer checks passed on reviewed head 5d3ac227f52b33fd0c32fddd479cb7296c4072a5. A disposable installed-CLI Python fixture reproduced the previous version/output/ignore mutations.
  • Gaps: cooperating Python scripts only; renderer YAML rewriting, automatic output isolation, repeated runs, same-project concurrency and full production lifecycle behavior were not established. Subprocesses are not a sandbox.

PR124: product authority and renderer contract

  • Relationship: new explicit contract; renderer parity unverified. R path.R dynamically discovers a root, while the thesis defines the project workflow.
  • Decision/rationale: current approved behavior supersedes defects and stale architecture claims. Root/path defaults must agree across projr, quarto::quarto_render() and RStudio QMD Render. Quarto root equals proj root; nested Quarto projects are unsupported. Direct rendering does not imply release lifecycle parity; R Markdown Knit is a separate entrypoint.
  • Implemented: PR124, merged 635aa9efac0d7a28971236ab78c879b21be5ec31, corrected AGENTS/README/flow guidance and added the behavior contract. This was documentation, not renderer code.
  • Executed evidence: independent document review and remote Rust CI passed at dbf8d5fd94a87bba32ffc95cd2ee3b47f1e04277.
  • Gaps: no direct R frontend, Quarto/RStudio GUI or fresh-render-session parity test was performed. No projr production code or thesis text was changed.

PR125: captured root and explicit selection

  • Relationship: different root-resolution mechanism; new CLI selection. R path.R calls root discovery from current context. The CLI now captures one absolute root and passes it to each managed child as PROJ_PROJECT_ROOT.
  • Decision/rationale: explicit selection wins, and path queries must not change projects after cwd changes. This deliberately improves unstable root behavior rather than copying it.
  • Implemented: PR125, merged f265eb46c91a300fe0aafad3119d998038946a0b; project.rs, ignore.rs, main.rs and build.rs. Direct library builds configure each child command instead of mutating the caller’s process-global root.
  • Executed evidence: three-platform tests at 779b3010040eeb23f08434478e0812173eb2a723 cover explicit precedence, spaces, invalid roots, changed cwd and overlapping builds in two distinct roots.
  • Gaps: marker discovery was not changed; R path helpers and direct render entrypoints do not yet consume this captured context. The tests do not promise general environment isolation or same-project concurrent builds.

PR126: nonmutating queries and initializer failure preservation

  • Relationship: same static read-only configuration intent; runtime R parity unverified. R yml.R reads/merges configuration; this does not establish equivalence of every R public path helper or its cache routing.
  • Decision/rationale: reading configuration or paths must not update ignore files. Mutating build/init operations request synchronization explicitly, and bad configuration must not replace custom ignores with default rules.
  • Implemented: PR126, merged cd34c3208f1ed1c3c27571e7ce2828498a4aecdb; yml.rs, build.rs, init.rs/main.rs.
  • Executed evidence: three-platform tests at cc132f1e1b288c7560ff6b6b06fcac369a475355 snapshot files/directories for CLI queries, exercise direct API reads and production ignore synchronization, and preserve custom ignores on malformed/read-failing config. Permission-denied coverage ran on Linux/macOS.
  • Gaps: supported aliases, unknown-option handling and effective merged script/hook configuration remained unchanged and incomplete.

PR127: operation failures and exit status

  • Relationship: new CLI transport contract; same failure-reporting intent. R build-engine.R uses R errors; that is not a process exit-code protocol for language wrappers.
  • Decision/rationale: a printed error must not be returned as successful execution. Failed Git remote inspection must not proceed to GitHub creation.
  • Implemented: PR127, merged 8e955b32bc1f611d38a8931d489de2bdfc50d5c7; main.rs routes operation failures to nonzero status and init.rs propagates previously swallowed external failures.
  • Executed evidence: three-platform tests at a741b5f9de63dcb96ca527607105e5547be1da7c cover failing queries/version/init/ ignores, missing executables, child failure and successful queries. Local fake Git/GitHub commands on Linux/macOS made no network requests.
  • Gaps: structured error/capability protocols and clean/idempotent Git-init coverage remained open; failure status is not rollback or R-runtime parity.

PR128: explicit noninteractive execution

  • Relationship: new CLI mode. The R baseline’s build-engine.R calls dependency helpers; no equivalent explicit CLI flag/parity is claimed.
  • Decision/rationale: machine invocations must not need the CLI’s prompts or automatic package installation. Controlled child stdin must actually be closed.
  • Implemented: PR128, merged f7ff7e92451a3174d6cb9c5fd60151621e66bd04 after independent review at 5dedee7da69cbe52837993e86bc4837c4c3342a1; adds the flag, inherited mode, runner stdin closure and controlled R-probe stdin closure.
  • Executed evidence: three-platform tests and installer checks passed at that head; fake-R EOF/no-install tests ran on Linux/macOS and Python runner-stdin coverage ran on all three platforms.
  • Gaps: no actual R startup/renderer execution comparison; initialization retains existing requested-operation defaults and third-party code can ignore EOF. This does not establish general subprocess isolation.

PR129: explicit empty selection and newly confirmed policies

  • Relationship: same absent-dev fallback; different explicit-empty guarantee. R yml-scripts.R falls back when dev scripts are absent. Empty-list behavior also passes through validation and renderer selection, so a reliable R upload-only no-analysis contract has not been demonstrated.
  • Decision/rationale: explicit [] selects no analysis, preserving hooks and production upload/export; absence still falls back. It must not discover or render unrequested files. Cleanup/promotion must preserve upload inputs.
  • Implementation status: PR129 removes the Dev-empty error and derives one analysis-selection guard for renderer setup/cleanup/promotion. tests/test_empty_scripts.rs checks hooks, existing output/docs bytes, actual production archive bytes and preview nonpublication.
  • Executed evidence: three-platform Rust tests and installer checks passed at f4b3739554dc548911019c450ca1e90a196d33d2; independent review inspected those logs and cleared that code head. The documentation-only final head 999b730fd2cc23215e4a07a1231d7d6fa3543966 passed all nine checks in runs 39486028024/39486028097 and independent review. Merged as 5617a6daed1f4743a9b2609694a2f84ad4c902eb; post-merge test, installer and site runs 39486858711/39486858532/39486858701 passed.
  • Gaps: YAML null-as-absence and malformed-list validation were inspected in source, not newly exercised by this policy slice. No R runtime empty-list parity test or real renderer execution is claimed.
  • Confirmed but separate runtime gaps: retain projr markers (including README/ VERSION), accept legacy _projr.yml with a both-base-files error, and use local > profiles > base with earlier profiles first. The R precedence evidence is yml.R. These approvals are recorded in the behavior contract; this change does not implement aliases, marker expansion or merged script/hook context.

Nearest recognized roots (current change)

  • Relationship: same static projr marker intent; deliberate extensions. projr path.R at 3ac2959 combines VCS, VERSION, README, R-package, RStudio, renv and Quarto criteria. Exact structured-marker patterns were checked in rprojroot root.R at 4d2f450.
  • Decision/rationale: retain those markers with nearest-wins; remove Rust’s VERSION-first/five-extra-ancestors heuristic. Add pyproject.toml and Julia Project.toml/JuliaProject.toml as requested language extensions. Proj config files also anchor a configured project without VERSION. Requirements/orphan manifests do not create roots. Explicit selection still wins.
  • Implementation/evidence status: root_from now tests each ancestor once, never child projects. tests/test_root_markers.rs covers retained marker patterns, invalid structured markers, weak/nested markers, deep invocation, explicit override and a configured Python preview with shallow enumeration. At code head a0d459c5b3a31437443832436535b70d34838553, all nine checks passed in runs 39487247962/39487247928. Independent review compared the pinned marker sources and inspected all three platform logs, clearing that head. Symlink normalization was source-inspected, without a new dedicated test. This evidence-only amendment requires its own checks; no R-runtime parity is claimed.
  • Gaps: required active config, explicit used-directory mappings, early unsupported-setting validation, legacy config-content aliases and full frontend/renderer parity are separate changes. A marker does not claim a Julia runner exists.
  • Ponytail full-mode review: reused the public root_from entrypoint, existing regex dependency and standard filesystem APIs, replacing the old special-case traversal instead of adding a discovery framework. Traced explicit/inherited precedence and all root callers. Kept discovery read-only and shallow, with runnable positive/negative predicates and workflow coverage; no new dependency.

Superseding configuration, failure and R-scope decisions

  • Relationship: different from prior convenience-default assumptions. The initial Rust/projr-style defaults and historical no-config fixtures are no longer the target behavior. Builds require active root-level configuration and explicit used-directory mappings; init may write familiar defaults into that file, but runtime must not invent missing directories or unknown subpaths.
  • Decision status: approved. The agreed _proj.yml / legacy _projr.yml names apply; explicitly activated profile files may provide configuration, while inactive profiles alone do not satisfy the requirement. Cwd discovery fallback does not waive build validation. Unknown behavior-affecting settings must fail before mutation.
  • Failure/publication target: restore pre-build state except permitted cache residue; storage/publication retry must not rerun or mislabel analysis. Existing staging/version/publication behavior does not yet prove that transaction.
  • Evidence/gaps: earlier CI entries remain accurate historical evidence for their source commits, not acceptance of the superseded no-config/default-path policy. Future fixtures must declare used paths and active configuration. The current core still needs enforcement and failure tests for the new rules.
  • Authorship boundary: the existing R package is entirely off limits, including root-helper fixes. A later backend port/integration must establish R parity; no such work or runtime comparison is claimed here. Thesis text remains untouched.
