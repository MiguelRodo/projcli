    Preview release delivery

    The reviewed pipeline prepares a draft prerelease for an existing vX.Y.Z-preview.N tag whose version exactly matches Cargo.toml. It does not bump versions, push commits, publish an APT repository, sign credentials or publish the draft automatically. No new release is implied by this documentation.

    Remote locked tests/builds produce Linux x86-64 and Windows x86-64 binaries. Linux uses Ubuntu 22.04 (glibc 2.35 or newer); the initial user-local WSL installation target is Ubuntu 24.04 x86-64. macOS/ARM delivery is not verified or supplied by this pipeline. Each asset is named proj_<version>_<os>_<arch>[.exe], with matching version.txt and checksums.txt. Exact-tag help/version/protocol smokes and actual installer tests must pass before assets enter the draft. Checksums detect corruption and mismatches; they are not independent signatures or reproducible-build attestations.

    Installers default to MiguelRodo/projcli, require version metadata and exactly one matching SHA256 entry, and verify downloaded bytes before replacement. They stage on the installation filesystem and need only an existing user-writable directory. PROJ_RELEASE_VERSION pins a release (with optional v); preview releases should always be pinned because GitHub’s latest URL normally selects stable releases. PROJ_INSTALL_DIR selects an existing absolute user directory without changing PATH or system settings. Existing older releases lacking the new metadata fail closed instead of installing an unverified fallback binary.

    Before publication: reconcile reviewed supported behavior and limits, update the Cargo/Cargo.lock preview version in a reviewed change, verify required checks, then create the exact reviewed tag. Inspect the resulting draft assets/version/ checksums and retain disposable-project warnings. Publish only after those checks. For WSL, download the pinned binary/manifest, verify SHA256, preserve any existing user-local binary, install into the chosen user-local directory and smoke help, version, capabilities and a disposable configured preview. No local compilation, sudo, persistent authentication change or R package modification is needed.

    Known limits include bounded captured-state recovery, arbitrary external script effects, incomplete direct R/IDE parity, incomplete attempt/release records and analysis-free publication retry. This is a development preview, not M2 completion.

    The prepared CLI package version is 0.4.0-preview.1; its review and the final integrated main checks precede creating tag v0.4.0-preview.1. Cargo.toml and the root proj entry in Cargo.lock match. proj --version and machine cli_version report that package version. proj version get reads an analysis project VERSION and is deliberately a separate value; existing project VERSION files are not bumped by preparing the CLI release. The feature status distinguishes implemented Rust behavior, pending recovery verification, R/IDE gaps and unfinished M2 records/provenance/retry. No broad milestone checkbox is closed merely to enable binary delivery.

    Verified delivery

    0.4.0-preview.1 is published as a prerelease; stable Latest remains v0.3.0. Its tag workflow passed, and both uploaded binaries were downloaded, hash-checked and executed for help/version/capabilities. Public downloads matched the verified asset bytes. Source identity is bbd12edc8de9865a96b6145d0c7702f1300cb1a8; package version is 0.4.0-preview.1, protocol version 1. The WSL user-local install and disposable Python success/failure smokes passed without local compilation. See compatibility evidence.

    Pin PROJ_RELEASE_VERSION=0.4.0-preview.1 when using the installer from that tag. Use an existing absolute user-local PROJ_INSTALL_DIR; installation changes no system/PATH settings. macOS/ARM artifacts remain unavailable. Keep the disposable- project limits and unfinished R/IDE/M2 scope from feature status.

    Next preview preparation

    The next-preview checklist records source integration, actual acceptance, reviewed version changes, exact-tag assets and WSL replacement. The published/installed preview remains 0.4.0-preview.1 until those steps complete. No new tag, release or installation is announced here. Bookdown site embedding remains native; other deferred limits stay explicit.

    Public README/install pins and public-download check expectations stay at the existing preview through tagging, draft validation, publication and public-byte verification. Update them together in a separate post-publication docs change: those CI checks fetch the public version and source-commit assets and cannot validate an unpublished pin. Release notes/version metadata can be prepared earlier.
